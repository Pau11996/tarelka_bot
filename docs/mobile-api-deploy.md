# Мобильный API на действующем сервере

Публичный адрес: `https://tarelkaa.by/api`. Используется текущий домен сайта и
его HTTPS-сертификат; отдельный DNS-поддомен не требуется. Демооплата остаётся
включённой по текущему решению.

## Что подготовлено в проекте

- `docker-compose.yml` запускает `mobile_api` с той же БД и AI-анализатором, что
  у бота. На хост порт API не публикуется: запросы проходят через nginx сайта.
- `mobile_media` — постоянный том с авторизованными фото/голосовыми, общий
  для API и бота. Он не обслуживается nginx как открытая статика.
- Внешний `/api/` nginx передаёт приложению без префикса; Uvicorn знает
  `root_path=/api`. Защищённые файлы также проходят через API, а не через
  обработчик статических картинок.
- Публичный API отказывается запускаться со стандартным или коротким JWT-секретом.
  Локальный override сохраняет отдельный режим разработки.
- Демооплата по умолчанию включена: `MOBILE_DEMO_BILLING=1`.

## Порядок развёртывания

1. Подключиться к действующему VPS, проверить папку проекта, конфигурацию
   nginx, текущие контейнеры и ревизию БД. Убедиться, что серверный бот поддерживает
   вход приложения через `/start app_<code>` и использует ту же БД.
2. Сохранить резервную копию БД. Доставить проверенные исходники и миграции до
   `022_email_password_reset`, сохранив серверный `.env`, данные и журналы.
   Локальный файл `.env` с тестовым ботом не переносить поверх серверного.
3. В серверном `.env` сохранить действующие `DATABASE_URL`, токен и username
   рабочего бота. Установить:

   ```dotenv
   MOBILE_JWT_SECRET=<отдельный случайный секрет, минимум 32 байта>
   MOBILE_DEMO_BILLING=1
   LANDING_PORT=127.0.0.1:8080
   ```

   Секрет можно получить командой `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.
   Он остаётся только в серверном `.env` и не встраивается в APK. Не менять уже
   существующий сильный секрет при обычных обновлениях: это разлогинит клиентов.
   Порт nginx в примере должен совпадать с текущим upstream внешнего nginx.
4. В HTTPS-блок действующего nginx добавить содержимое
   `deploy/nginx-mobile-api.location.conf`. Он сохраняет префикс `/api` до
   контейнера сайта и задаёт размер загрузки/таймауты на внешнем прокси.
   Проверить конфигурацию через `sudo nginx -t`, затем перезагрузить nginx.
5. Из папки проекта на VPS собрать и запустить API и сайт:

   ```sh
   docker compose build mobile_api landing
   docker compose up -d --no-deps mobile_api landing
   docker compose ps
   docker compose logs --tail=50 mobile_api
   ```

   Анализатор должен уже работать. API применяет миграции перед запуском.
   Для сервера используются только основной compose и серверный `.env`,
   без `docker-compose.local.yml`. Не удалять том `mobile_media` при обновлениях.
6. Проверить с внешней сети:

   ```sh
   curl --fail https://tarelkaa.by/api/health
   curl -i https://tarelkaa.by/api/v1/me
   ```

   Первый запрос возвращает `{"status":"ok"}`, второй без токена — `401`.
   Затем выполнить вход и контрольные запросы из отдельного тестового аккаунта,
   включая загрузку фото больше 1 МБ и получение защищённого изображения.

## Следующий шаг — APK

После успешной проверки серверного адреса сборка приложения должна содержать:

```dotenv
EXPO_PUBLIC_API_URL=https://tarelkaa.by/api
EXPO_PUBLIC_DEMO_BILLING=1
```

Это параметры будущего самостоятельного APK. Локальный Expo Go может продолжать
использовать LAN-адрес API. Серверная подготовка сама по себе не создаёт релизный APK.

## Локальная проверка подготовки

25 октября 2026: 579 серверных/рендерных тестов прошли. Compose-конфигурации
production и local проверены отдельно: демооплата включена, production API не
публикует порт на хост, у бота и API один постоянный том.

Отдельный временный nginx-контейнер успешно передал `/api/health`, JSON и
multipart-загрузку 2 МБ. Неавторизованные `/api/v1/me` и защищённое изображение
с расширением `.jpg` возвращают `401`; API-ответы имеют `Cache-Control: no-store`.
Проверены синтаксис обоих nginx-прокси и относительный редирект `/api` → `/api/`.
Серверные исходники подготовлены; фактический VPS требует отдельного подключения
и проверки существующей конфигурации.
