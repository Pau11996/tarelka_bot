# ТАРЕЛКА 1.0.7

Android versionCode: 8. Профиль EAS preview, API `https://tarelkaa.by/api`.
Выпуск APK для скачивания с лендинга.

## Изменения

- Вход через Google на Android: системный выбор аккаунта, проверка подписанного
  токена на сервере и одноразовой заявки. Существующий дневник, профиль и подписка
  сохраняются при подключении Google к подтверждённому email; для сторонней почты
  дополнительно требуется пароль от дневника.
- Картинка «Поделиться нормой» собирается из выбранных значений и готового шаблона
  на сервере, без нейросети. Предпросмотр и отправка используют один PNG. Для
  подготовки картинки требуется интернет; доступны повтор и отмена.
- Обновлены тексты приветствия, убраны лишние подписи в чате, деталях дня и подписке.
- Подсказки в полях входа и регистрации стали прозрачнее.
- Письма подтверждения почты и восстановления пароля получили HTML-оформление:
  крупный код в отдельной рамке, срок действия и текстовая версия для почтовых клиентов.
- Объяснение Health Connect свёрнуто по умолчанию и описывает общее хранилище
  данных здоровья на телефоне.

## Совместимость и настройка

Сначала обновить API и применить миграцию `027_google_login`, затем публиковать APK.
В серверном `.env` задать публичный идентификатор:

```dotenv
GOOGLE_WEB_CLIENT_ID=780700822279-f3nj0h75ra5emeubp7kphgljlg6620ot.apps.googleusercontent.com
```

Android OAuth-клиент для `by.tarelka.app` и подписи APK зарегистрирован в том же
Google-проекте. Client secret не используется. Пакет и сертификат подписи нового
APK должны совпадать с 1.0.6. Текущие лимиты подписок не меняются; индивидуальный
`daily_request_limit` по-прежнему имеет приоритет.

## Проверки и публикация

Локально пройдены TypeScript, 312 мобильных тестов и 727 серверных и HTML-тестов.
SQL миграции PostgreSQL сгенерирован и проверен.
После оформления писем повторно пройдены 46 тестов регистрации, восстановления
пароля и Google-входа, включая MIME-версии письма и TLS. Оба письма проверены
в браузере при ширине 320 пикселей; код остаётся целым и не выходит за рамку.

Проверить TypeScript, мобильные и серверные тесты, SQL миграции, подпись и версию
APK. Проверить Google start endpoint, отказ для неверных токенов и неавторизованной
выгрузки нормы; в приложении — открытие, подготовку картинки и системное меню
отправки. Полный Google-вход проверить с разрешённым аккаунтом на устройстве.

Релизный коммит сначала отправить в GitHub и подтвердить наличие в удалённой
ветке согласно `AGENTS.md`. APK собирать из чистой копии этого коммита. Сервер
обновлять через Git, предварительно сохранив БД, `.env`, предыдущие образы и APK.
После обновления API опубликовать APK, проверить полную публичную загрузку
и записать результат в `outputs/releases/release-1.0.7-status.json`.
