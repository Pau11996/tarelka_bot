# Цели по весу и достижения

Одна система данных для приложения и Telegram-бота. Общие правила находятся в
`src/shared/weight_tracking.py`, расписание — в `src/shared/weight_reminders.py`.
Бот вызывает сервисы напрямую; HTTP-контроллеры используют те же сервисы.

## Поведение

- Вес записывается числом через «Записать вес», без AI и расхода AI-лимита.
  В чатах приложения и Telegram распознавание веса из текста, голосовых и фото
  отключено. Анализатор обрабатывает только питание, воду и активность; старый
  ответ типа `weight` отклоняется без записи веса или еды. Ранее сохранённые
  измерения и карточки истории остаются доступны. Ключ операции/сообщения
  защищает ручной ввод от повторной записи.

- Цель и еженедельное напоминание необязательны и доступны без подписки.
- Цель сохраняет стартовый вес, желаемый вес, направление и время начала.
  Одна активная цель обеспечивается ограничением БД. Изменение желаемого веса
  архивирует предыдущую цель; одинаковый целевой вес повторно её не запускает.
- Направление согласовано с профилем. При активной числовой цели отдельное
  конфликтующее изменение направления профиля возвращает 409.
- Дальнейшие изменения цели и измерения не пересчитывают калории. Первичное
  заполнение профиля рассчитывает норму, как раньше. Необязательный желаемый вес
  сохраняется с первой анкетой в одной транзакции.
- Новое актуальное измерение автоматически завершает цель снижения или набора
  веса при достижении ориентира. Цель сохраняется в истории; последующие колебания
  веса её не открывают. Запись, завершение и поздравление фиксируются одной
  транзакцией. Старая запись до начала цели и открытие сводки её не завершают.
- Поддержание веса остаётся наблюдением без автоматического завершения.
  В боте новый ориентир, равный текущему весу, предлагает продолжить учёт или
  указать другой вес; существующие цели поддержания сохраняются.
- При достижении веса автоматически сохраняется поздравление в истории чата
  приложения с кнопкой «Открыть достижения». Оно создаётся в транзакции измерения
  из формы, профиля или Health Connect. На каждую цель приходится только одно
  сообщение, включая повторные запросы и повторное пересечение цели. При выбранном
  доступном канале Telegram бот также отправляет постоянное сообщение с кнопками
  «Задать новую цель» и «Вес и цель»; очистка служебных сообщений его не удаляет. Фоновая доставка проверяет
  очередь раз в 5 секунд. Неопределённый результат Telegram не повторяется, чтобы
  исключить дубли; сообщение приложения остаётся доступным. Поддержание веса
  не создаёт поздравления о завершении.
- Каждое явное взвешивание создаёт запись даже при том же значении. Повторный
  запрос с тем же ключом операции возвращает имеющуюся запись. Другой вес с тем же
  ключом возвращает 409. Обновление остальных полей профиля измерением не считается.
- Источники текущего веса — ручные записи и уже сохранённые данные Health Connect.
  Побеждает более позднее время измерения; при одинаковом времени — ручная запись.
  Будущие измерения не участвуют. Импорт не меняет ручной профиль и не копируется
  в ручную историю; остановка новых импортов не удаляет сохранённую историю.
- Награды остаются только в интерфейсе приложения: первое взвешивание, 4/12 недель измерений подряд, 7/30 дней дневника
  подряд, завершение цели. Выдаются однократно, сохраняются после прерывания серии.
  Самая первая запись устанавливает начальный вес. «Первое взвешивание» выдаётся
  только за следующую запись (включая тот же вес); повторная доставка первой записи
  и изменение остальных настроек профиля её не выдают. Учитываются оба интерфейса
  и Health Connect. Миграция 021 снимает преждевременную награду у аккаунтов,
  имеющих только начальную запись.
  Исторические серии учитываются при вычислении наград; прогресс ещё не полученных
  наград показывает текущую серию. Заработанные награды материализуются при записи
  веса, завершении цели и загрузке достижений, в том числе по старой истории.

## Напоминания

По умолчанию выключены; начальное расписание — понедельник, 09:00, часовой пояс
аккаунта. Неделя начинается в понедельник. Любое измерение этой недели подавляет
напоминание. Планировщик запускается в процессе бота раз в минуту и использует
общий канал аккаунта: Telegram или приложение. Новое включение требует доступного
канала; ранее включённое расписание при глобальном отключении остаётся сохранённым,
но доставка приостанавливается.

Ограничение БД `(user_id, week_start)` предотвращает повторные недельные события.
Неопределённый результат отправки Telegram не повторяется автоматически.
Пропущенные дни не догоняются. Перед отправкой повторно проверяются настройки и
измерения; ожидающий push отменяется, если измерение уже пришло или день прошёл.
На каждом зарегистрированном устройстве создаётся не больше одной доставки события.

Telegram-напоминание сохраняет кнопки «Записать вес» и «Отключить это напоминание».
Служебная очистка его не удаляет. `/notifications_off` приостанавливает также
взвешивания; отдельное выключение взвешиваний не затрагивает другие уведомления.
Веб и Expo Go не получают системный push; используется существующее ограничение
приложения. Для проверки push нужна отдельная сборка на физическом устройстве.

## HTTP-интерфейс

Все маршруты требуют Bearer-токен и работают только с текущим аккаунтом.

- `GET /v1/chat`: поле `notices` содержит постоянные сообщения о достижении цели
  (`id`, `title`, `message`, `created_at`) для общей хронологии чата.
- `GET /v1/chat/notices`: те же сообщения для фонового обновления открытого чата
  без повторной загрузки дневника и сброса ранней истории.
- `GET /v1/achievements`: `goal`, `goal_history`, `current_weight_kg`,
  `latest_measurement`, `weight_history`, `achievements`, `reminder`.
- `PUT /v1/weight-goal`: `target_weight_kg`, `expected_goal_id` (null для новой),
  `expected_weight_kg` для проверки сводки перед сохранением. Устаревшая сводка
  возвращает 409. Ответ — обновлённые достижения.
- `POST /v1/weight-goal/complete`: `goal_id`; требуется фактически достигнутый вес.
- `DELETE /v1/weight-goal?goal_id=…`: отмена, история сохраняется.
- `POST /v1/weight`: `weight_kg`, `operation_id`. UUID генерирует приложение;
  при сетевом повторе того же измерения UUID сохраняется. Ответ остаётся совместимым
  с прежним API профиля. Старые клиенты без UUID поддерживаются.
- `PUT /v1/settings/weigh-in-reminder`: `enabled`, `weekday` (0=пн…6=вс),
  `local_time` (`ЧЧ:ММ`). Ответ содержит состояние доставки и причину недоступности.
- `PUT /v1/profile`: необязательный `target_weight_kg` при первичном заполнении.
  Поле не влияет на `is_complete`. Повтор начальной анкеты не перезаписывает
  устаревшими данными уже сохранённый профиль и цель.

Приложение использует вкладку `/achievements` и форму `/weight`; push допускает
только разрешённый внутренний маршрут `/weight`.

В Telegram основная команда `/weight` открывает «Вес и цель»: текущий вес с датой,
целевой вес, изменение от старта и оставшиеся килограммы. Кнопки: «Записать вес»,
«История» / «Изменить цель», «Настройки». Без цели можно продолжать взвешивания
или нажать «Задать цель». История показывает последние 20 измерений и 5 прошлых
целей. Напоминание и отмена цели находятся в настройках; процентов и наград нет.
Старые `/achievements`, кнопки достижений/наград и ручного завершения открывают
новую сводку. Старые ссылки на отмену сохраняют подтверждение.

В форме записи принимается только число в кг, с точкой или запятой. Фото,
голосовые и текст вместо числа получают подсказку о ручном вводе без загрузки
вложений, обращения к AI и расхода AI-лимита. Обычные сообщения чата не создают
измерений веса.
Цель создаётся через короткое подтверждение текущего и желаемого веса; без известного
веса сначала запрашивается текущее измерение.

## Выпуск и проверки

Перед запуском новой версии API и бота применить миграцию:

```sh
.venv/bin/alembic upgrade head
```

Текущая ревизия — `021_achievement_messages` (цели добавлены в `020_weight_goals`). Существующие пользователи не получают
автоматически созданную цель или включённое напоминание. Нужны перезапуск API и
бота (новый роутер, команда меню, планировщик), затем обновление клиента.
Текущая модель входа через email и Telegram сохраняется; общие данные доступны
через один `user_id`, в частности при входе приложения через Telegram.
Упрощение Telegram-раздела и автозавершение новых измерений не требуют новых
миграций и не меняют API. Для включения логики нужно обновить и API, и бота.

Для локального Docker API, используемого Expo на телефоне, обновление выполняется
командой `docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build --no-deps mobile_api`.
Локальный контейнер API применяет миграции перед запуском. Перезапуск только
Expo не обновляет серверный образ; отсутствие нового маршрута в старом образе
возвращает `404 Not Found` во вкладке достижений.

Тесты: `tests/test_weight_tracking.py`, `tests/test_weight_bot.py`, мобильные
`recordWeight.test.cjs`, `weightTracking.test.cjs`, расширенные тесты профиля и
графиков. Серверные тесты используют изолированную SQLite-базу; Telegram и push
проверяются через подменённые клиенты без отправки реальных сообщений.
