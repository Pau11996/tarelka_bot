# Тренировки в приложении

Пятая вкладка приложения: **Чат · Дневник · Прогресс · Избранное · Тренировки**.
Доступна всем авторизованным пользователям без подписки. В Telegram нет каталога
или плеера; добавленная активность видна в общем дневнике.

## Каталог и демонстрации

Источник — `src/shared/workouts.py`: шесть подготовленных комплексов, 14 упражнений,
11 собственных SVG-анимаций. Занятия собираются редакционно, без генерации ИИ.
Продолжительность карточки вычисляется из времени движений, ожидаемого времени
повторов и отдыха. В этой версии все движения выполняются стоя; необходимая стена
и пространство указаны в карточке. Спортивный инвентарь и коврик не нужны.

Тексты и персонаж созданы для «Тарелки». Ориентиры для техники:

- [NHS: Strength and flex videos](https://www.nhs.uk/live-well/exercise/strength-and-flex-exercise-plan-how-to-videos/)
- [NHS: Strength exercises](https://www.nhs.uk/live-well/exercise/strength-exercises/)
- [NHS: Flexibility exercises](https://www.nhs.uk/live-well/exercise/flexibility-exercises/)
- [Compendium: Conditioning exercise](https://pacompendium.com/conditioning-exercise/)

Позы находятся в `mobile/src/workouts/poses.ts`, отрисовка — в
`ExerciseFigure.tsx`. Учитываются системное уменьшение движения и уход приложения
в фон. Звук перехода встроен в APK; внешние видео и медиа-сервер не требуются.

Каталог имеет версию. После публикации **нельзя менять состав и MET существующей
версии**: добавляйте следующую в `CATALOGS`, сохраняя предыдущие для отложенных
результатов. Клиент v1 принимает только совместимый каталог v1. Для новых типов
анимации сначала выпускается клиент с поддержкой этих ресурсов.

## Состояние и синхронизация

`engine.ts` считает фактическое время монотонными часами, отдельно от календарной
даты. Повторы завершаются явным нажатием. Задержанный таймер переводит только один
шаг: следующий не считается выполненным за время зависания. Для повторов есть
предел учёта времени — четыре ожидаемые длительности, затем включается пауза.

`WorkoutStore` сохраняет шаг примерно каждую секунду, при действии и при уходе
в фон. После перезапуска предлагается продолжение с паузы. При аварийном
завершении процесса может потеряться последний незаписанный интервал около секунды.
Экран удерживается включённым только во время активного прохождения.

Каталог, настройки, текущий шаг, история и очередь результатов хранятся локально.
Ключ включает хеш адреса API, ID аккаунта и версии авторизации. Другой аккаунт
не получает эти данные; завершение старого запроса после выхода их не переносит.
Удаление аккаунта очищает его локальное хранилище. Обычный выход оставляет кеш
этого аккаунта для повторного входа.

Повторная отправка происходит при старте, возвращении в приложение, открытии
раздела и каждые 20 секунд при наличии очереди. Потеря ответа после успешной
записи безопасна: UUID и хеш неизменяемого тела предотвращают дублирование.
При ошибке локальной записи занятие ставится на паузу; результат не объявляется
сохранённым, пока запись не удалась. Без сети оценка калорий ожидает сервера.

## API и дневник

Все маршруты требуют обычной авторизации. ИИ, лимиты запросов и Health Connect
при сохранении не вызываются.

| Метод и путь | Назначение |
| --- | --- |
| `GET /v1/workouts/catalogue` | Версионный каталог |
| `GET /v1/workouts/history?offset=0&limit=30` | История и `next_offset` |
| `PUT /v1/workouts/sessions/{uuid}` | Идемпотентное сохранение результата |
| `GET /v1/settings/workouts` | `auto_log` и `sound` |
| `PUT /v1/settings/workouts` | Обновление настроек аккаунта |
| `POST /v1/workouts/sessions/{uuid}/diary` | Идемпотентный перенос в дневник |

Настройка `auto_log` по умолчанию выключена. Её значение фиксируется при начале
занятия, поэтому изменение настройки не меняет уже начатую тренировку.
Прерванные занятия не переносятся в дневник. Если пропущены все упражнения,
занятие считается прерванным. Частично выполненное движение учитывается по
фактическому времени, но не считается завершённым упражнением.

Сервер рассчитывает приблизительные активные калории:
`sum((MET - 1) × 3.5 × вес_кг / 200 × активные_секунды / 60)`.
Отдых и паузы исключены. Используются категории Compendium: лёгкая гимнастика
3.5 MET, упражнения с весом тела 3.0, мягкая растяжка 2.3. Это оценка категории
активности, а не индивидуальное измерение. Сохраняются вес и версия расчёта.

Без веса результат сохраняется с `calories: null`. Пользователь может указать
вес и вручную добавить занятие позже. Дата дневника определяется началом занятия
и сохранённым часовым поясом, а не временем синхронизации.

Сессия и обычный `DayEntry(ACTIVITY)` создаются в одной транзакции; изменения
одного аккаунта сериализуются блокировкой строки `User` в PostgreSQL. Запись
увеличивает `activity_bonus` по существующим правилам дневника. При её удалении
FK становится `NULL`, а `diary_added` остаётся `true`: повторная синхронизация
не восстанавливает удалённое. Импорт Health Connect остаётся отдельной историей
и, как раньше, не создаёт `DayEntry` и не начисляет калории.

## Проверка и выпуск

Автоматические проверки:

```sh
npm run typecheck --prefix mobile
npm test --prefix mobile
.venv/bin/python -m pytest -q
cd mobile
npx expo export --platform android --output-dir /tmp/tarelka-android-export
```

`mobile/tests/workouts.test.cjs` проверяет таймер, паузы, восстановление, пропуски,
повторы, дополнительный отдых, очередь, потерянный ответ, смену аккаунта и ошибки
диска. `tests/test_workouts.py` проверяет API, расчёт, настройки, удаление аккаунта,
дату, повторную отправку, дневник и миграцию с откатом.

Перед выпуском на физическом Android проверить полный проход, звук и его
отключение, повторы, блокировку экрана, фон, принудительное закрытие,
авиарежим/возврат сети и выход с повторным входом в другой аккаунт. Проверить
технику всех демонстраций, размеры шрифтов и пять вкладок на маленьком экране.
Браузерный проход не заменяет проверку этих нативных функций на устройстве.

Порядок выпуска: опубликованный в GitHub релизный коммит → `alembic upgrade head`
(ревизия `024_workouts`) → перезапуск API → проверка API → сборка и публикация APK
из того же опубликованного коммита. Следовать `AGENTS.md`: если push ещё не сделан,
остановиться до обновления сервера и публикации APK. Новая версия приложения
требует развёрнутого API тренировок.
