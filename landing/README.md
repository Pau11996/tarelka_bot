# Лендинг и блог

Сайт остаётся статическим: nginx, HTML/CSS/JS и подстановка разрешённых переменных через `envsubst`. Новых зависимостей в Docker-образе нет.

Публичные ссылки на бота и его адрес в JSON-LD используют `LANDING_BOT_USERNAME` (по умолчанию `taarelka_bot`, без `@`). Настройка независима от `TELEGRAM_BOT_USERNAME`: последний должен соответствовать токену бота в текущем окружении и используется для Telegram-входа в админку. Поэтому локальный тестовый бот не подменяет ссылки на продового бота на лендинге.

## Страницы

- `/` — главная, `public/index.template.html`.
- `/blog/` — список статей.
- `/blog/tochnost-kalorij-po-foto/` — ограничения фотооценки.
- `/blog/kalorijnost-gotovogo-blyuda/` — формула и калькулятор порции.
- `/blog/dnevnik-pitaniya/` — инструкция и CSV-шаблон.
- `/about/` — сервис, редакционные принципы, контакты.

`home.css` оформляет главную и общие элементы новых страниц; `blog.css` — статьи и карточки. `styles.css` также используется юридическими страницами и админкой.

## Добавление статьи

1. Создать `public/blog/<slug>/index.template.html` на основе существующей статьи.
2. Задать уникальные title, description, H1, canonical `${LANDING_ORIGIN}/blog/<slug>/`, OG и Twitter. Использовать единый адрес с завершающим `/`.
3. Обновить видимый текст и JSON-LD BlogPosting/BreadcrumbList: headline, url, image, автор и фактическая дата изменения. Не указывать будущую или вымышленную дату публикации.
4. Добавить локальную обложку, ссылки на источники, связанные материалы и карточку в `public/blog/index.template.html`. Обновить список `blogPost` в JSON-LD индекса блога и видимое количество статей.
5. Добавить контекстную ссылку на материал из уже существующей страницы, чтобы он не оказался изолирован.
6. Запустить проверки. Тест сейчас ожидает 8 индексируемых URL; при добавлении страницы обновить это ожидаемое число.

`docker-entrypoint.sh` сам находит вложенные шаблоны, создаёт HTML и добавляет canonical индексируемых страниц в sitemap. Не нужно вписывать URL в отдельный список. Исходные `.template.html` nginx не отдаёт.

Непроверенную статью не следует класть в публичный каталог: отсутствие ссылки само по себе не делает URL закрытым.

## Проверки без Docker

```sh
python3 -m unittest discover -s landing/tests -p 'test_*.py'
node landing/tests/recipe-calculator.test.cjs
node landing/tests/analytics.test.cjs
sh -n landing/docker-entrypoint.sh
```

Тесты Python используют стандартную библиотеку, `sh` и установленный `envsubst`. В проекте должен быть Node.js для проверки JS-калькулятора.

Для локального рендера сначала скопировать `landing/public` во временный каталог. Затем:

```sh
LANDING_PUBLIC_DIR=/tmp/tarelka-site \
LANDING_RENDER_ONLY=1 \
LANDING_ORIGIN=https://tarelkaa.by \
sh landing/docker-entrypoint.sh
```

Не запускать рендер непосредственно в `landing/public`: он создаёт файлы с подставленными значениями рядом с шаблонами. Проверять редиректы и CSP нужно через nginx с `nginx.conf.template`; простой файловый HTTP-сервер не воспроизводит эти правила.

## Калькулятор и шаблон

`recipe-calculator.js` считает ккал на 100 г и на порцию из суммы калорий и готового веса. Обработчик формы предотвращает отправку данных; до запуска JS поля выключены. Некорректные значения очищают предыдущий результат.

`public/downloads/dnevnik-pitaniya.csv` — пустой шаблон на неделю: UTF-8 с BOM, разделитель `;`, 12 колонок. Он не связан с пользовательскими данными бота.

## Google Analytics 4

Поток сайта: `G-DBX8MSSJDK`; переопределение — `GA_MEASUREMENT_ID`. Все публичные страницы подключают `analytics.js`, админка исключена. Google tag загружается только после согласия посетителя. Отказ, отзыв и изменение выбора доступны через «Настройки аналитики» внизу страницы. Согласие сохраняется на 180 дней. Рекламные consent-параметры остаются `denied`, Google Signals и персонализация отключены.

Обычные просмотры localhost не отправляются в GA4. Для явной проверки на локальном сервере используйте `http://127.0.0.1:8080/?analytics_debug=1`, затем разрешите аналитику. Такие события имеют `debug_mode: true` и предназначены для DebugView. Вкладки с другими страницами при локальной проверке также должны иметь `?analytics_debug=1`. На продовом домене разрешённый `LANDING_ORIGIN` включает сбор автоматически после согласия. Данные калькулятора и дневника не передаются.

События, параметры и оставшиеся настройки кабинета: [ANALYTICS.md](ANALYTICS.md).
