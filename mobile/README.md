# Тарелка · мобильное приложение

Expo SDK 58 / React Native 0.88. Главный экран — чат дневника. Два независимых способа входа: email с паролем создаёт новый дневник; Telegram открывает существующий аккаунт бота с его записями, профилем и подпиской. Автоматического объединения аккаунтов нет.

## Локальный запуск

1. Сделать резервную копию БД. Применить миграции до `022_email_password_reset` (`alembic upgrade head`). Существующие аккаунты Telegram сохраняются.
2. `docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build`
3. В `mobile/.env`: `EXPO_PUBLIC_API_URL=http://<LAN-IP-компьютера>:8001`. Для web на компьютере — `http://127.0.0.1:8001`. Телефон не может обращаться к localhost компьютера; API должен быть доступен в локальной сети или через HTTPS.
4. Установить Expo Go для SDK 58 на Android. `cd mobile && npm ci && npm start -- --lan --port 8082`. Expo Go и проект должны использовать одну версию SDK.

`npm start`, `npm run android` и `npm run ios` открывают проект в Expo Go. Для установленной development build: `npm run start:dev -- --lan --port 8082`.

Превью в браузере: `npx expo start --web --port 8082`. Камеру, микрофон, системные переходы и push обязательно проверить на телефонах.

## Тестовые сборки iOS / Android

- В `app.json` указан EAS Project ID `857cec7e-bc63-4d60-a028-04648c5f9820`. Для сборки нужен аккаунт Expo с доступом к этому проекту. `EXPO_PUBLIC_EAS_PROJECT_ID` позволяет переопределить его при работе с отдельным проектом.

- Профиль `preview` уже задаёт `EXPO_PUBLIC_API_URL=https://tarelkaa.by/api` и демооплату. Локальный LAN-адрес в `mobile/.env` можно сохранить для Expo Go. Для других профилей адрес API задаётся отдельно через окружение EAS.
- `npx eas-cli build --profile development --platform android` / `--platform ios`.
- Android: установить APK. iOS internal build требует учётную запись Apple Developer и регистрацию устройства.
- Для установки без Metro: профиль `preview`.
- Для push настроить APNs и FCM v1 в Expo/EAS. Пока project ID и credentials отсутствуют, экран уведомлений объясняет недоступность и позволяет оставить Telegram.

## Демооплата

В сборке `EXPO_PUBLIC_DEMO_BILLING=1`, на API `MOBILE_DEMO_BILLING=1`. Только готовая тестовая карта, успех / отказ. Ни платёж, ни подписка не создаются. По текущему решению демооплата остаётся включённой и в первом публичном APK. При подключении настоящей оплаты оба демофлага нужно будет заменить соответствующей интеграцией.

## Навигация и интерфейс

На экране входа доступны «Создать аккаунт», «Войти по email» и «Войти через Telegram». Обычная регистрация сразу открывает пустой дневник и не обращается к Telegram. Пароль — от 8 до 128 символов; он хранится как отдельный salted PBKDF2-HMAC-SHA256 хеш (600 000 итераций). Попытки регистрации и входа ограничиваются в БД, общей для API workers. Восстановление забытого пароля доступно через «Забыли пароль?» во входе по email. Подтверждение email при регистрации пока не подключено.

API: `POST /v1/auth/email/register` (`email`, `password`, необязательный `timezone`) и `POST /v1/auth/email/login` (`email`, `password`). Обе операции возвращают обычный access token. Email нормализуется без учёта регистра. `/v1/me` и `/v1/settings` показывают способ входа; Telegram-уведомления доступны только аккаунтам Telegram.

Восстановление: `POST /v1/auth/email/forgot-password` (`email`) отправляет шестизначный код, `POST /v1/auth/email/reset-password` (`email`, `code`, `password`) меняет пароль. Код действует 10 минут, хранится как HMAC и используется один раз; повторная отправка заменяет предыдущий код. Ограничения: одно письмо в минуту и пять в час на адрес, десять в час на IP; пять проверок кода за 10 минут на адрес и 30 на IP. После смены пароля все предыдущие токены аккаунта становятся недействительными; требуется обычный вход.

Перед запуском обновлённого API применить `alembic upgrade head` (миграция `022_email_password_reset`), затем задать `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` (`starttls`/587 либо `ssl`/465), `SMTP_USERNAME`, `SMTP_PASSWORD` и `SMTP_FROM` в окружении API. Отправитель должен быть разрешён почтовым провайдером; для почты с двухфакторной защитой обычно нужен отдельный пароль приложения. TLS и проверка сертификата обязательны. Без SMTP экран честно показывает временную недоступность; письма не имитируются. Тесты перехватывают доставку и не отправляют реальные письма. Перед публикацией проверить доставку на своём тестовом адресе.

Для входа через Telegram бот должен обрабатывать `/start app_<code>` и подтверждать код в той же БД, что использует API. Если текущий бот обслуживает «Свисток», обработчик входа нужно согласовать с ним или использовать отдельного бота; одновременный polling двух процессов с одним токеном не работает.

В нижней панели — чат, дневник, прогресс и избранное; статистика находится внутри дневника. Плашка «Аккаунт» справа сверху открывает отдельные экраны профиля, подписки, уведомлений, приглашений, помощи и управления данными. Старый адрес `/settings/personal` перенаправляет в `/profile`.

Звёздочка на карточке еды в чате, дневнике и подробном просмотре сохраняет запись в избранное; повторное нажатие убирает её. Состояние приходит с сервера вместе с записью и сохраняется после повторного входа. Статистика сахара и клетчатки доступна без подписки за базовый период: графики, сумма, среднее по дням с данными и количество записей, где показатель известен. Отсутствующие значения не заменяются нулями; неполные итоги помечаются.

В избранном «Порядок» открывает весь список для перестановки за ручку справа. У края экрана список прокручивается; доступны клавиши ↑/↓ и действия экранного диктора. «Готово» сохраняет общий порядок для приложения и Telegram-бота, «Отмена» отменяет черновик. В боте кнопка «Изменить порядок» открывает стрелки ↑/↓ и страницы по восемь записей. Новые записи появляются сверху. При одновременном изменении списка другим клиентом нужно обновить его и повторить перестановку; повтор сохранения после потери ответа безопасен. Приложение загружает общий порядок при открытии вкладки и возвращении из фона.

Для выпуска этой функции сначала применить миграцию `023_favorite_order` и обновить API/бота, затем публиковать сборку приложения. Миграция сохраняет прежний порядок существующих записей. API: `PUT /v1/favorites/order`, тело `{favorite_ids, original_ids}` содержит новый и исходный полные списки ID; конфликт возвращает HTTP 409.

Достижение дневного лимита открывает отдельное окно со счётчиком и временем обновления в часовом поясе аккаунта. Оно работает для фото, текста, голосовых и исправлений, включая ошибки фоновых заданий. При активной подписке окно объясняет восстановление доступа без повторной продажи; переход к подписке предлагается только когда она увеличит текущий лимит. После отказа текст и локальные фото возвращаются в черновик. В истории остаётся короткое уведомление с кнопкой информации; старые текстовые ошибки лимита также отображаются компактно.

При первом появлении последней ошибки лимита в истории окно открывается автоматически, в том числе после возвращения в чат. Показанное окно не открывается повторно при опросе истории или переходах между экранами; кнопка информации остаётся доступна. На карточке еды «Уточнить» находится справа, звёздочка избранного — непосредственно слева от неё.

Чат открывается на последних сообщениях; загрузка ранних записей сохраняет место чтения. Карточка анализа компактная: небольшое фото сбоку, название, калории и БЖУ. Отправленные фото показываются миниатюрами; нажатие открывает фото на весь экран без обрезки. Просмотр закрывается крестиком или кнопкой «Назад» на Android. «Подробнее» в карточке открывает состав и порции, дополнительные нутриенты и пояснения анализа. При отправке видны загрузка вложений, очередь и анализ; состояние обработки сохраняется после выхода из чата.

Вес вводится числом через «Записать вес», без обращения к AI. Распознавание веса из фото, текста и голоса в чате отключено. История измерений и старые карточки чата сохраняются.

Для одновременной проверки web и телефона можно отдельно задать `EXPO_PUBLIC_WEB_API_URL`, оставив LAN-адрес в `EXPO_PUBLIC_API_URL` для нативного приложения.

Плавающий помощник перемещается жестом и закрепляется у ближайшего края. Положение сохраняется между запусками и адаптируется к размеру экрана. При вводе сообщения, записи голоса и работе с фото он скрывается.

## Данные и задания

`MOBILE_MEDIA_DIR` — закрытый постоянный том, общий для API и бота. Локально `/opt/mobile-media`. Не публиковать этот каталог nginx. Доступ к файлам проходит через авторизованный API.

Защищённые фото загружаются обычным `fetch` с токеном аккаунта. На телефоне используется общий дисковый кэш для чата, подробностей и полноэкранного просмотра; компонент `Image` получает только локальный URI. Это обходит потерю HTTP-заголовков в Android Image. Фото сохраняются между переходами и перезапусками приложения в пределах одной сессии входа, пока ОС не очистит cache. Лимит — 100 МБ и 100 фото: сначала удаляются давно неиспользуемые изображения, открытые фото сохраняются до закрытия. Одновременные запросы одного фото объединяются; закрытие одного просмотра не отменяет загрузку для другого. При выходе или смене аккаунта кэш очищается, незавершённые загрузки отменяются. Повреждённый файл удаляется из кэша для повторной загрузки. После 30 секунд доступен повтор. В web общий кэш object URL действует до перезагрузки страницы или выхода.

Worker запускается вместе с API. Задания записываются в БД, выполняются с блокировкой, а изменение дневника и результат задания фиксируются одной транзакцией. Прерванное задание после 15 минут становится доступным для повторения. Фото/аудио сохраняются вместе с историей; удаление записи или аккаунта очищает соответствующие вложения.

Push ставятся в сохраняемую очередь; канал выбирается в профиле. При неопределённом сетевом результате отправки push возможен повтор доставки: транспорт Expo не даёт гарантии exactly-once.

## Android: Health Connect

Миграция `019_health_connect` добавляет отдельные таблицы подключений, дневных итогов,
измерений и квитанций синхронизации. Перед применением сделать резервную копию PostgreSQL.
Флаг API `HEALTH_CONNECT_ENABLED=1` включает подключение; по умолчанию в приложении сервера
он выключен. Локальный compose включает его после применения миграции.

В меню аккаунта → «Устройства и здоровье» пользователь разрешает чтение шагов,
расстояния, **активных** калорий, тренировок и веса. Часы сначала должны выгрузить
данные в приложение производителя, а оно — в Health Connect на Android-телефоне.
Если тренировки приходят из нескольких приложений, нужно выбрать один источник.
Дневные итоги берутся через Aggregate API Health Connect, без суммирования сырых шагов.

Работает только в нативной Android-сборке. Expo Go, web и iOS показывают объяснение
и не загружают нативный модуль. Для разработки:

```bash
cd mobile
npm ci
npx expo run:android
npm run start:dev -- --lan --port 8082
```

`expo run:android` требует JDK 21 и Android SDK/NDK версий проекта. Для APK через EAS:
`npx eas-cli build --platform android --profile preview` (нужен настроенный EAS project).
Для магазина: профиль `production`, публичный HTTPS API и публикация обновлённой
`landing/public/privacy.template.html` по `/privacy.html`. В Play Console заполнить
Health apps declaration для запрашиваемых разрешений. APK debug подходит для локальной
проверки, не является подписанным релизом для магазина.

После явного подключения импортируются последние 30 дней. При открытии/возврате
в приложение выполняется foreground-синхронизация, не чаще раза в 5 минут;
«Обновить данные» запускает полную сверку доступной истории. Фоновых разрешений нет.
Changes API учитывает обновления/удаления отдельно по каждому типу. При просроченном
токене выполняется полная сверка. Если Android больше не даёт прочитать старый диапазон,
он сохраняется в облаке, а повторно сверяются последние 30 дней.

SQLite хранит очередь пакетов до серверного подтверждения, Changes cursors и индекс
интервалов удаляемых записей. Scope включает API, аккаунт и ID установки. Повтор пакета
идемпотентен; оптимистическая ревизия защищает от устаревшей записи. Курсоры продвигаются
только после подтверждения всех пакетов. Выход останавливает текущие/ожидающие загрузки
и очищает локальное состояние; другой аккаунт требует явного подключения. Один аккаунт
синхронизируется с одним телефоном; замена требует отдельного действия в интерфейсе.

Импортированные данные не создают DayEntry, не расходуют AI-лимиты, не продлевают серию,
не меняют `activity_bonus`, норму питания и вес профиля. Измерения Health Connect
добавляются к истории веса с происхождением. Отсутствующие данные отображаются как «—»,
измеренный ноль сохраняется. Дни рассчитываются сервером по часовому поясу аккаунта,
с учётом переходов летнего времени; старые итоги другого часового пояса скрыты до сверки.

Отключение оставляет историю. «Удалить данные устройств из ТАРЕЛКИ» удаляет импорт
и останавливает синхронизацию, сохраняя ручные записи и оригиналы в Health Connect.
Удаление аккаунта также удаляет все таблицы импорта. Приложение ничего не записывает
обратно в Health Connect, не читает маршруты, сон и пульс. Данные импорта не передаются
AI-провайдерам или рекламе. Отдельный нативный экран объяснения доступен из системного
окна разрешений, даже без входа в аккаунт или загрузки JavaScript.

Проверка: `npm test` (очередь, Changes, перезапуск после потери ответа, разрешения,
смена аккаунта, Expo Go/web), `npm run typecheck`,
`.venv/bin/pytest tests/test_health_connect.py tests/test_mobile_api.py` из корня.
Миграция проверяется на отдельной PostgreSQL базе с upgrade/downgrade/upgrade.
Обязательный ручной проход на телефоне: подключение, частичный отказ, отзыв доступа,
повторный импорт, удаление/исправление измерения в Health Connect, отсутствие сети,
смена источника, выход и другой аккаунт. Реальная передача с часов требует устройства
и приложения производителя, записывающего данные в Health Connect.
